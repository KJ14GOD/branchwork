Add a membership operator to the saved-search language in this repository, so that a saved search can ask whether a field is any one of several values. `npm test` currently fails because the tests for it are already written and the operator does not exist.

Spelled `in`, with the options separated by bars: `state in open|blocked|closed` matches a record whose `state` is any of the three. It reads as an operand kind of its own — a list rather than a scalar — because the operand text has to become several values before anything can compare against it.

What the operator has to do, in the three places an operator lives in this package (README.md names them):

- Declared in the operator table in src/tokenize.js with id `isOneOf`, spelling `in`, and operand kind `list`, and read by the lexer into an array of options. Whitespace around an option is not part of it: `open | blocked` is the two options `open` and `blocked`. An empty option is a SyntaxError whose message contains the words "empty option".
- Implemented in src/evaluate.js under the id `isOneOf`, matching when the field equals any option. Compare on the string form of the field, exactly as `equals` already does, so a record whose `priority` is the number 2 satisfies `priority in 1|2`.
- Described in src/explain.js under the same id, as `<field> is one of <options>`. One option reads `state is one of open`. Two read `state is one of open or blocked`. Three or more take commas and a final "or": `state is one of open, blocked, or closed`.

Constraints. Do not edit anything under tests/ — the tests describe the operator correctly and are the specification. Do not change the module paths or the names those modules already export, and do not change what the operators that already exist do. src/query.js is glue and should not need to learn about this operator; if you find yourself special-casing membership in it, the change is in the wrong file.

A hidden test you cannot see will be run against these modules after you finish. It imports src/tokenize.js, src/evaluate.js and src/explain.js directly as well as through src/query.js, and it uses option counts and spacing the visible tests do not, so an implementation whose three halves only agree on the exact cases in the visible suite will not count as finished.

Run the tests when you are done and report what they actually said.
